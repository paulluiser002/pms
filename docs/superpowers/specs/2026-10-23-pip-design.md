# Performance Improvement Plan

Add a branded PIP module visible to every role. Employee access is confined to their own plans; managers configure and assess direct reports in the current company; HR configures organization plans. Preserve existing evaluations, NTEs, and journals.

Automatic enrollment uses authoritative completed and released KPI evaluation snapshots. Confirmed user rule: at least one verified indicator below its target. Only KPI results qualify; behavioral failures and incomplete/unverified records do not. Record the failure rule and frozen source indicators, results, template criteria and cycle. Synchronization is idempotent across refresh and subsequent plan closure. An open plan receives an additional referral instead of duplicate enrollment, with visible planning/review needs; historical plans stay immutable. No automatic disciplinary or employment outcome.

Auto records await Manager/HR planning. Manual enrollment requires a reason and may use any measured source indicator from a permitted evaluation or a manually declared indicator if no evaluated source exists. Staff declare editable weekly sections, normally one indicator per week: focus indicator, measurable improvement goal, target, unit, direction, improvement actions, manager support/resources and seven-day period. Targets are explicit PIP criteria, independent of source scores. Dates cannot overlap and activation requires complete sections and a start date on/after the app workflow day. Planning can be saved as a draft. Activation locks existing goals, dates, and targets and notifies the employee.

Employee sees source, weekly timeline, expectations, support and status, acknowledges the plan, saves updates, and submits a numeric actual plus progress narrative/evidence link or reference for an available week. Future weeks are locked. Late submission is allowed with an overdue indicator. Manager/HR reviews submissions, enters verified actuals and assessment remarks, and assesses against the weekly target; can return a submission with a correction reason. Submitted updates and assessments remain recorded. Failed weeks can receive additional follow-up weeks with a mandatory extension reason; assessed evidence is never replaced. Staff can close only after all weeks are assessed and any additional referrals are reviewed: Completed if all final linked follow-up outcomes meet target; Not Met otherwise. Missing employee submissions can be assessed after the deadline only with explicit reason and observed actuals, never an inferred zero. Cancellation requires a reason. Plan history records creation, referral, activation, acknowledgement, submission, return, assessment, extension and outcome.

Screens: scoped listing with search/status filters and summary counts; manual enrollment; planning builder; plan detail with frozen source evidence, weekly timeline, actionable cards and history; employee weekly progress; Manager/HR weekly assessment; extension, cancellation and final-outcome confirmations. Existing notification menu links to PIP actions. Empty, forbidden, future week, overdue, draft, pending assessment, returned, and closed states must be explicit. Working local screens are the requested prototypes; no new visual theme or dependencies.

Implementation follows the current vanilla JavaScript / browser-local storage prototype. System workflow date follows urToday; actual audit timestamps use pdNow. Real multi-user delivery/auth remains outside this local prototype.
